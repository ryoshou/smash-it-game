# Milestone 1 — Shooting Prototype Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A device build where you drag a slingshot down and release it. A yarn ball flies on a pure gravity arc into one desk of placeholder keycaps, hits feel strong, and the round is judged (desk cleared, or out of shots once things settle). This is owner checkpoint 1 (spec §10a): it confirms the shot feel.

**Architecture:**
- Every rule is a plain C# class driven by EditMode tests: pull→velocity, gesture state, trajectory preview, impact and clear rules, shot budget, round judging, level layouts.
- Thin MonoBehaviours own the Rigidbodies, touch input, the view and feedback. `GameBootstrap` owns the model and ticks it.
- Feedback only listens to `GameEvents`. Gameplay code never references it.
- Every number lives in a `ShotTuning` ScriptableObject that is cloned at runtime.
- The scene, prefabs and prototype levels are generated by editor scripts, so they can be rebuilt from code.

**Tech Stack:**
- Unity 6000.6.0f1 with 3D URP (`com.unity.template.urp-blank`) and PhysX 3D physics.
- Input System (EnhancedTouch, with TouchSimulation in the editor).
- uGUI and Unity Test Framework (NUnit), plus `com.unity.testtools.codecoverage`.

## Review Focus

1. **Dragging up, sideways past the pouch, or back into the pouch.**
   - The shot cancels, isn't spent, and nothing fires.
   - Tests: `Compute_UpwardPull_Cancels` and `Compute_TinyPull_Cancels` (Task 2), `Release_BackInPouch_CancelsAndDoesNotSpend` (Task 9).
2. **A second finger lands mid-pull, or the app is backgrounded mid-pull.**
   - The second finger is ignored, and pausing cancels without firing.
   - Tests: `SecondTouch_IsIgnoredWhileHolding` and `Cancel_WhileHolding_ReturnsToIdleWithoutFiring` (Task 3).
3. **A level's stack wobbles or falls on its own at spawn.**
   - Nothing counts as cleared, and everything settles within 2 s without a shot.
   - Test: `PrototypeLevels_AreStableAtSpawn` (Task 8).
4. **The last shot leaves a keycap teetering, or a prop jitters forever.**
   - A topple during the settle wait is a win, and endless jitter is judged at `settleMaxWaitSeconds`.
   - Tests: `SlowToppleDuringSettle_Wins` and `NeverSettles_JudgedLostAtMaxWait` (Task 6).
5. **The ball comes to rest on the desk, wedges somewhere, or falls out of the world.**
   - It despawns, so judging is never blocked.
   - Test: `ShouldDespawn_*` (Task 5).

### Task 2: ShotTuning and SlingshotMath

**Files:**

**Interfaces:**
- Produces:
  - `ShotTuning : ScriptableObject` with public fields and these defaults:
    - Pull and aim: `maxPull=0.25f, minPull=0.03f, grabRadius=0.08f` (all in screen heights), `minSpeed=4f, maxSpeed=9f, minElevationDeg=8f, maxElevationDeg=22f, maxYawDeg=25f, reloadSeconds=0.5f, gravityY=-9.81f`.
    - Preview: `previewSeconds=0.2f, previewDots=8`.
    - Ball: `ballRadius=0.09f, ballMass=0.25f`.
    - Impact: `impactSpeedMultiplier=1.6f, burstStrength=0.6f, burstRadius=0.35f, objectMaxLinearSpeed=6f, objectMaxAngularSpeed=20f`.
    - Settling and clearing: `settleLinearThreshold=0.05f, settleAngularThreshold=0.25f, settleHoldSeconds=0.6f, settleMaxWaitSeconds=5f, clearMargin=0.15f`.
    - Ball despawn: `ballLifetimeSeconds=4f, ballRestSpeed=0.15f, ballRestMinAge=1f, ballKillY=-1f`.
    - Continue: `continueShots=3`.
    - Methods: `static ShotTuning CreateDefault()` and `ShotTuning Clone()`.
  - `readonly struct LaunchResult { bool Fired; Vector3 Velocity; float Power01; static LaunchResult None; }`
  - `static class SlingshotMath { static LaunchResult Compute(Vector2 pull, ShotTuning t); }`. `pull` = (finger − pouch) / screen height, so a downward drag has negative y. World +z points toward the desk.

Algorithm (fixed by the spec's "pull further = faster and higher", left/right aims):

```
if pull.y >= 0 or |pull| < minPull → None
len   = min(|pull|, maxPull);  power = clamp01((len − minPull) / (maxPull − minPull))
yaw   = clamp(atan2(−pull.x, −pull.y) in degrees, ±maxYawDeg)      // drag left → aim right
speed = lerp(minSpeed, maxSpeed, power);  elev = lerp(minElevationDeg, maxElevationDeg, power)
velocity = speed × (cos elev · sin yaw, sin elev, cos elev · cos yaw)
```

**Interfaces:**

### Task 6: ShotBudget, RoundJudge and GameEvents

**Files:**
- Create: `Scripts/Runtime/Core/{ShotBudget,RoundState,RoundJudge,GameEvents}.cs`
- Test: `Assets/Tests/EditMode/RoundTests.cs`

**Interfaces:**
- Produces:
  - `sealed class ShotBudget`
    - `ShotBudget(int shots)`, `int Remaining`
    - `bool TryConsume()`
    - `bool CanContinue`: true until a continue is used in this attempt.
    - `bool TryContinue(int extraShots)`
    - `void ResetAttempt(int shots)`: refills and re-enables continue.
  - `enum RoundState { Playing, Won, Lost }`
  - `sealed class RoundJudge`
    - `RoundJudge(float holdSeconds, float maxWaitSeconds)`, `void Reset()`
    - `RoundState Evaluate(float now, int targetsRemaining, int shotsRemaining, bool ballActive, bool anyMoving)`
  - `sealed class GameEvents` holds plain C# events, raised only by gameplay:
    - `event Action<float> PullChanged` (power 0–1)
    - `event Action<Vector3> Fired` (velocity)
    - `event Action<Vector3, float, bool> Impact` (point, speed, isFirstContact)
    - `event Action<int> TargetCleared` (remaining)
    - `event Action<RoundState> RoundEnded`
    - Each has a matching `Raise…` method.

RoundJudge rules, evaluated in this order:
1. `targetsRemaining == 0` → Won.
2. `shotsRemaining > 0 || ballActive` → Playing, and clear both timers.
3. Otherwise:
   - Start the wait timer on the first evaluation.
   - Track the "quiet since" time: reset it when `anyMoving`, and set it on the first quiet frame.
   - Lost when quiet for ≥ `holdSeconds`, or waiting for ≥ `maxWaitSeconds`. Else Playing.
