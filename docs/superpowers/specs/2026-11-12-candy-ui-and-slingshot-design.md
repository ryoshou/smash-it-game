# Candy UI, monolithic slingshot, simple ball: design

Date: 2026-11-12 · Owner: Ryoshou · Status: draft for owner review

## Why

The owner plays on an iPhone 17 and feels the UI "doesn't look good": the flat cream pills and coral button blend into
the warm orange room and read as a prototype, not a finished mobile game. The reference for the *feeling* is Royal
Smash (clean-room: we aim for the same polish, we copy none of its art, icons, layouts or text). The slingshot still
reads as "assembled pieces", and the yarn ball is a placeholder until a proper asset is found.

Success: on the owner's phone every screen reads as one confident, bright, tactile game style, and the frame rate is
unchanged.

## Goals

1. **Style A, "candy buttons"**, across every screen: home, HUD, pause/settings, win, lose, room map, splash.
2. **Home layout as the owner set it** (mockup `ui-style-a3.html`, kept under `.superpowers/brainstorm/`):
   - top-left: purple level badge ("★ Level N");
   - top-right: round yellow **gear icon** (Settings), and directly **under it** a small red **No Ads** button;
   - title "SMASH IT" (yellow, outlined, slight tilt) with a small "cat chaos!" line under it (wording: builder's call,
     goes through `UiStrings`);
   - middle-low: big green **PLAY**; **Rooms** (blue) **centred under Play**.
3. **HUD**: level badge left, yarn-balls-left badge centre/right, round pause button right; same candy look; stays
   inside the safe-area margins from 3be759a.
4. **Win screen**: dimmed scene, cream panel with a yellow "LEVEL CLEAR!" ribbon, a line of text, green NEXT, and blue
   Replay / Home under it. **No stars.**
5. **Slingshot**: one continuous carved wooden Y (handle flows into the arms with no visible joints, balls or seams).
   **Keep** the cord grip and the red band wraps, but make them **match**: part of the same shape (flush, sunk into
   the wood, same smooth shading and a palette that sits with the wood), not rings stuck on.
6. **Ball**: no CC0 yarn model was found (searched 2026-11-12; only paid or custom-licence models). Use a **simple
   smooth ball** now; it is replaced later when an asset is found.

## Non-goals

- Stars, ratings, currencies, new screens or features (the owner: "leave it for later").
- Changing what any button does, the flow between screens, or the save.
- Gameplay, physics, camera, pouch position, band anchors, ShotTuning: approved feel stays frozen.
- The cat, the rooms, the props.

## Anti-goals (would be a failure even if it works)

- **Outlines too thick.** The owner explicitly asked to balance them: thin dark outlines (about 2 px at the mockup's
  220 px phone width, i.e. roughly 2–2.5% of a button's height), a short solid lip shadow under buttons, light text
  stroke. Bold, not heavy.
- Anything that costs frame rate: extra cameras, post-processing, per-frame UI rebuilds, big textures, new packages.
- Anything that looks copied from Royal Smash.
- Real emoji glyphs in the game (they render differently per device). Icons are drawn sprites.

## Look (from the approved mockup)

| Element | Fill | Outline / lip |
|---|---|---|
| Primary (Play, Next) | green gradient, light top → darker bottom | dark green |
| Secondary (Rooms, Replay, Home) | blue gradient | dark blue |
| No Ads | red gradient, small | dark red |
| Round icon buttons (gear, pause) | yellow-orange gradient | brown |
| Badges (level, yarn left) | purple gradient (yarn: orange) | dark purple / brown |
| Panels | cream gradient | brown, rounded, with a coloured ribbon header |
| Title | yellow text | brown stroke + short drop |
| Text on buttons | white | thin stroke in the button's dark colour |

Lilita One stays the font. Pressed buttons keep the existing `ButtonPress` squash.

## Constraints (project rules that apply)

- UI, scene and sprites are generated by editor scripts (`UiStyle`, `UiSceneParts`, `MetaSceneParts`); never hand-edit
  `.unity` / `.prefab` / `.asset` / `.meta`. Generated art goes under `Assets/_Game/Art/Generated/` with a row in
  `docs/asset-licenses.md`.
- No packages or SDKs; no downloads without the owner's OK.
- Player-visible text lives in `UiStrings`.
- Slingshot: generated by `tools/blender/props/slingshot.py`, ≤ 1,500 triangles, `BandAnchorL/R` stay at
  (±0.13, 0, 0.192) (`ArtAssetsTests`). Ball: same 0.18 model diameter so `SlingshotSceneParts` scaling is unchanged.
- Performance: gradients, outlines and lips baked into a few small 9-sliced sprites tinted per colour (one atlas-able
  set), icons as small generated sprites; UI layout is static (no per-frame layout changes); no new canvases beyond
  what exists.
- iOS builds only; re-export after the change and remind the owner to Clean Build Folder.

## Left to the builder

- How the gradient/outline/lip sprites are generated and composed (one sprite per look vs. layered tinted sprites),
  as long as the outline stays thin and the draw cost stays flat.
- Exact sizes and spacing on other screens (pause/settings, lose, room map, splash), following the home and win
  mockups.
- Icon drawing (gear, pause, map, no-ads, home, replay, next), procedurally generated in the editor.
- How the slingshot is modelled as one mesh (e.g. a single swept/skinned curve or a merged and remeshed body) and how
  the wraps are made flush; colours of wood, grip and wraps, chosen to match each other and the candy UI.
- The ball's colour (keep the current pink family).
- The "cat chaos!" subtitle wording.

## Owner calls recorded

- Style A, with the home layout above (2026-11-12).
- Gear icon instead of a "Settings" label; no stars; thinner outlines.
- Slingshot: one piece; keep grip and wraps but matching.
- Ball: online yarn asset if one exists, otherwise a simple ball for now.
