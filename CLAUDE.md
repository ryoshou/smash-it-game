# smash-it-game — portrait mobile physics game (cat + slingshot knocks things off a desk), Unity 6000.6 (3D URP)

## Goal right now
M3 "Room 1 complete" per `docs/superpowers/plans/2026-11-03-m3-room1-complete.md` → owner checkpoint 3 (25 Home
Office levels, all screens, save, simulated ads + Remove Ads). The final cat is deferred to checkpoint 4 (owner): the
blockout cat stays. Approved feel is frozen: don't change existing ShotTuning defaults, keycap colliders/masses, camera,
pouch or ball physics. No real ad/IAP/consent/analytics SDKs until M4. iOS builds only.

## Layout
- `Assets/_Game/Scripts/Runtime/` → `Game.Runtime.asmdef`
  - `Core/` pure rules: ShotTuning, SlingshotMath, SlingshotGesture, TrajectoryMath, ImpactMath, SettleMath,
    ClearRule, BallLife, ShotBudget, RoundJudge, GameEvents
  - `Meta/` pure app rules: SaveData/SaveCodec/Profile (save), AppFlow (screens), AdPacing, AppConfig, UiStrings (all
    player-visible text) · `Monetization/` IAdService/IPurchaseService + simulated implementations (M4: MAX, IAP)
  - `Levels/` LevelDef, LevelList, PropCatalog, PrototypeLevels · `World/` DeskObject, YarnBall, BallPool, LevelSpawner
  - `Controls/` SlingshotInput · `View/` SlingshotView · `UI/` Hud, ResultPanel, DebugTuningPanel
  - `Juice/` feedback (listens to GameEvents, never referenced by gameplay) · `Audio/` sfxr synth (ported from ant-game)
  - `GameBootstrap.cs` owns and ticks the round · `AppController.cs` owns the app around it (flow, save, panels, ads)
- `Assets/_Game/Scripts/Editor/` → `Game.Editor.asmdef`: PrototypeAssetBuilder, PrototypeSceneBuilder, BuildScripts
- `Assets/_Game/Config/` ScriptableObject assets · `Assets/_Game/Levels/` level data · `Assets/_Game/Scenes/Game.unity`
- `Assets/_Game/Art/` Packs/ (copied by `tools/assets/import-packs.sh` from `pack-manifest.txt`), Generated/ (Blender output), Materials/
  — every file needs a row in `docs/asset-licenses.md`; `ArtPostprocessor` + `ArtCheck` enforce budgets on import
- `Assets/Tests/EditMode|PlayMode/` test asmdefs · `tools/unity/*.sh` CLI helpers (compile, tests, build)
- Not in git: `download-assets/` (CC0 packs, source for M2), the original game's APK and videos (untrusted, never run).

## Architecture
- Game rules are plain C# in `Core/` and `Levels/`, driven by EditMode tests. MonoBehaviours only own Rigidbodies,
  route input, render and play feedback.
- Every gameplay number lives in `Config/ShotTuning.asset` (feel in `JuiceConfig.asset`). `GameBootstrap` clones it at
  runtime so the debug panel never edits the asset. Never hardcode gameplay numbers.
- Scene, prefabs and prototype levels are generated by editor scripts (`Smash/…` menus). Rebuild, don't hand-edit.
- World: 1 unit = 1 m. Desk top at y = 1.0, desk centered at the origin, +z points away from the player.

## Code conventions
- Namespace `Game.<Folder>`. Never a `Game.Physics` namespace (shadows `UnityEngine.Physics`). One MonoBehaviour per file.
- `[SerializeField] private` over public fields (ScriptableObject tuning fields may be public).
- No `GameObject.Find` / `FindObjectOfType` at runtime; no allocations in `Update`/`FixedUpdate`.
- New scripts go in the correct asmdef folder — never in `Assets/` root.

## Tool routing (MUST follow)
| Task | Route |
|---|---|
| Write/edit C# | Edit files directly, then `tools/unity/compile.sh` and `unity command console --level error` before saying done |
| Scenes, GameObjects, prefabs, assets | Editor scripts or `unity command eval_file --file <scratch.cs>` (body-only). NEVER hand-edit `.unity` / `.prefab` / `.asset` / `.meta` YAML |
| Packages | `unity command package_add` / `package_remove`, then wait for domain reload |
| Tests | `tools/unity/edit-tests.sh [Fixture]`, `tools/unity/playmode.sh` (editor open); `tools/unity/batch-tests.sh editmode|playmode [--coverage]` (editor closed) |
| Pack models | add a line to `tools/assets/pack-manifest.txt`, run `tools/assets/import-packs.sh`, add the license row |
| Generated models | edit `tools/blender/…` scripts, run `tools/blender/build.sh [name]` (never hand-edit fbx) |
| Build | `tools/unity/build.sh ios` (Android deferred until release) |
| Visual check | `tools/unity/snapshot.sh out.png [level] [--break] [--cat Take:s]` (editor closed) or `unity command capture_game_view` |
| Level balance | `tools/unity/playtest-bot.sh` (editor closed; `SMASH_BOT_ROOMS="2 3"` picks rooms, `SMASH_BOT_LEVELS="26,27"` re-plays global level numbers) rewrites `docs/playtest/room<N>-report.*`; re-run after any layout change or `PlaytestReportTests` fails |
| Editor builders | `tools/unity/run-method.sh Game.Editor.PrototypeSceneBuilder.Rebuild` rebuilds props, vfx, sounds, rooms (`Editor/Rooms/`), cat, levels (`Editor/Levels/`, joined by `GameLevelListBuilder`) and the scene |
| Blender tests | `tools/blender/build.sh --tests`; authored models: Blender +Y = Unity +Z (export bakes the turn) |

- Always pass `--caller plugin --skill <skill>` on `unity command` calls; `--format json` when parsing.
- After package/asmdef changes the Editor domain-reloads; poll `unity command editor_status` until it answers.

## Testing
- TDD with EditMode tests for all pure logic; ≥ 80% line coverage of `Game.Core` and `Game.Levels`.
- PlayMode tests: spawn stability, preview-vs-flight, the game loop. No tests for feel, VFX or UI look.

## Don'ts
- Don't copy anything from the original game (art, audio, levels, code). Never install or run its APK.
- Don't add packages or SDKs without asking. Don't change ProjectSettings unless a plan says so.
- Don't commit `Library/`, `Temp/`, `Logs/`, `UserSettings/`, `Builds/`, `.superpowers/`, `download-assets/`.
- Binary art/audio/fonts/models go through Git LFS (patterns in `.gitattributes`).
